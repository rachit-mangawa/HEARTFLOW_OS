# 1. Lead-II ECG Oscillograph and Web Serial Hardware Bridge

Date: 2026-10-18

## Status
Accepted

## Context
HEARTFLOW_OS claims clinical-grade cardiovascular inference deployed at the edge. However, the telemetry monitoring UI previously displayed generic scalar trend lines (Heart Rate and Body Temperature) rather than physiological electrophysiological waveforms. In cardiology, clinician trust requires authentic Lead-II electrocardiographic (ECG) tracing displaying the canonical P-Q-R-S-T sequence.

Furthermore, while the repository includes C-compilation toolchains and ESP32 PlatformIO firmware (`firmware/src/main.cpp`), the telemetry pipeline in the browser previously relied on synthetic mathematical generators with no mechanism to ingest live data from physical microcontrollers connected via USB.

## Decision
1. **60 FPS Lead-II GPU Oscillograph**:
   - Implement an HTML5 `<canvas>` oscilloscope rendering a real-time Lead-II cardiac vector at 60 FPS.
   - Morph the waveform morphology dynamically according to the classification state generated by the ensemble:
     - **Normal Sinus Rhythm**: Standard P wave, PR segment (160ms), sharp QRS spike (1.2mV), isoelectric ST segment, rounded T wave.
     - **Tachycardia / Elevated HR**: Compressed R-R interval.
     - **Heart Attack Risk / Ischemia**: Pathological **ST-segment elevation (STEMI)** above baseline.
     - **Arrhythmia / Ectopy**: Premature Ventricular Contractions (PVC) with widened, inverted QRS complexes and compensatory pauses.
   - Render over medical-standard 1mm / 5mm grid lines with a sweeping phosphor persistence radar line.

2. **Web Serial Hardware Bridge**:
   - Implement a browser-native Web Serial API bridge (`navigator.serial`) operating at 115,200 baud, matching the ESP32 firmware configuration in `firmware/platformio.ini`.
   - Provide a bidirectional serial terminal reader capable of ingesting structured comma-delimited packets (`$HR,SPO2,SYS,DIA,TEMP*CHECKSUM\n`).
   - Implement an internal **Silicon Loopback Simulator** ensuring evaluators without physical microcontrollers plugged in can still inspect and execute the hardware packet parser.

3. **Auditory Telemetry**:
   - Integrate a lightweight Web Audio API pulse tone modulated by heart rate and $SpO_2$ saturation, muted by default with a mechanical toggle switch.

## Consequences

### Positive
- Bridges the gap between web software and embedded hardware by allowing direct physical USB connection to microcontrollers.
- Transforms the visual perception of the platform from a "web chart" to an authentic ICU telemetry workstation.
- Fully aligns the frontend telemetry ingestion with the existing C PlatformIO firmware.

### Negative / Trade-offs
- Web Serial API is restricted to Chromium-based browsers (Chrome, Edge, Opera) in secure contexts (`localhost` or `HTTPS`). The Silicon Loopback Simulator mitigates this by providing 100% feature coverage on all browsers.
- HTML5 Canvas redraw at 60 FPS consumes incremental client CPU/GPU; optimized using integer rasterization and fixed-length buffer circular arrays.
